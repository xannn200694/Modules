# Design

## Context

См. proposal.md, раздел Why. Сейчас `composer.json` требует PHP `>=5.6.4` и `illuminate/*` `5.3.*`. Команды реализованы через `fire()`, `str_slug()` и `studly_case()`. Конфигов phpcs, phpstan, phpunit и Compose нет. Контракт загрузки уже опубликован в `openspec/specs/module-boot/spec.md`.

## Goals / Non-Goals

**Goals:**

- Сделать пакет загружаемым на PHP 8.5 и Laravel 13 без смены поведения `module-boot`.
- Дать три завершающиеся команды Compose, которые в WSL проверяют PSR-12, phpstan уровня 5 и сценарии `module-boot`.

**Non-Goals:**

- Каркас приложения Laravel, HTTP-сервис и код хоста `xannn94/larakhan`.
- Новый состав шаблона модуля. Генератор продолжает отдавать текущий контракт хоста.
- Перенос `module-boot` на строгое сравнение `enabled`.

## Decisions

### Платформа — стабильные релизы на 9 ноября 2026

Образ и ограничение PHP — 8.5.12 / `^8.5`. PHP 8.6 на эту дату ещё кандидат, стабильный релиз назначен на 19 ноября. Laravel — `illuminate/*` `13.40.*`: это линия релиза 13.40.0, ей нужен PHP `^8.3`, значит 8.5 подходит. Альтернатива «самый новый номер версии, включая кандидат» отложена до стабильного 8.6.

### В require только то, что импортирует src

Остаются `illuminate/support`, `console`, `filesystem`, `config`, `database` и `laravel/framework`, все `13.40.*`. Класс `Illuminate\Foundation\Application`, которым типизирован `Modules`, в Laravel 13 лежит в `laravel/framework`: отдельного пакета `illuminate/foundation` `13.40` на Packagist нет (там только заброшенный пакет 1.x). `illuminate/routing` по-прежнему не указан в `require`: его импортирует сгенерированный шаблон, а шаблон исполняет хост.

### Команды переводятся на API Laravel 13

`fire()` заменяется на `handle()`. `str_slug()` заменяется на `Str::slug()`, `studly_case()` на `Str::studly()`. Поведение отбора кэша не трогаем: его фиксирует `module-boot`.

### Проверки живут в dev-зависимостях и Compose

`require-dev`: phpcs со стандартом PSR-12, phpstan с уровнем 5, phpunit и `orchestra/testbench` `^11.3`. Выпущенный Testbench 11.3 требует `laravel/framework` `^13.32` и поднимает фреймворк внутри теста. Каталога приложения в репозитории нет. Тега `11.6` на Packagist нет.

Compose описывает один сервис PHP 8.5 с рабочим каталогом репозитория. Команды `docker compose run` запускают `vendor/bin/phpcs`, `vendor/bin/phpstan` и `vendor/bin/phpunit` и завершаются. Порт не публикуется. Запускать их нужно из дистрибутива WSL: файл Compose не кодирует Windows-пути.

PSR-12 и уровень phpstan 5 — стартовые пороги. Уровень можно поднять отдельным изменением, когда базовый прогон зелёный.

## Risks / Trade-offs

- [`laravel/framework` тянет большое дерево пакетов] → Это плата за тип `Application` в публичном конструкторе. Выделение более узкого контракта — отдельное изменение.
- [PSR-12 и phpstan уровня 5 сначала красные] → Порт команд и форматирование входят в то же изменение, прогон считается готовым только при коде 0.
- [Testbench поднимает больше фреймворка, чем `require`] → Тест проверяет поведение `module-boot`, а не состав production-зависимостей. Состав `require` проверяется отдельно по `composer.json`.
- [Образ 8.5 перестанет быть «самым новым» после 19 ноября] → Спецификация говорит «PHP 8.5». Смена мажорной ветки PHP — новое изменение.

## Migration Plan

Потребители пакета переходят на PHP 8.5 и Laravel 13 вместе с этим релизом. Данных для миграции нет. Откат — вернуть прежние ограничения `composer.json` и вызовы `fire()` / `str_slug()` / `studly_case()`. Проверки после отката на PHP 8.5 не рассчитаны.
