# Spec Delta

## Purpose

Фиксирует, какие модули приложение поднимает при старте: boot читает кэш модулей и регистрирует отобранные записи.

## ADDED Requirements

### Requirement: Загрузка из существующего кэша

Пока файл кэша модулей существует, система SHALL выбирать модули для старта из этого файла и MUST NOT читать манифесты модулей.

#### Scenario: Кэш расходится с манифестом

- **WHEN** файл кэша существует, и у модуля значение `enabled` в манифесте отличается от записи кэша
- **THEN** система отбирает модуль по записи кэша

### Requirement: Отбор по enabled

Система SHALL отбирать запись кэша, когда её `enabled` равен boolean `true` по нестрогому сравнению, и MUST NOT отбирать запись в остальных случаях.

#### Scenario: Включённый модуль

- **WHEN** у записи `enabled` равен boolean `true`
- **THEN** система отбирает эту запись

#### Scenario: Выключенный модуль

- **WHEN** у записи `enabled` равен boolean `false`
- **THEN** система не отбирает эту запись

#### Scenario: Поле enabled отсутствует

- **WHEN** у записи нет поля `enabled`
- **THEN** система не отбирает эту запись

#### Scenario: Число 1

- **WHEN** у записи `enabled` равен числу `1`
- **THEN** система отбирает эту запись

#### Scenario: Строка true

- **WHEN** у записи `enabled` равен строке `true`
- **THEN** система отбирает эту запись

#### Scenario: Строка 1

- **WHEN** у записи `enabled` равен строке `1`
- **THEN** система отбирает эту запись

### Requirement: Порядок регистрации

Система SHALL регистрировать отобранные модули по возрастанию поля `order`. Запись без `order` SHALL идти раньше записи с числовым `order`.

#### Scenario: Меньший order раньше

- **WHEN** отобраны модуль с `order` `1` и модуль с `order` `10`
- **THEN** система регистрирует модуль с `order` `1` раньше модуля с `order` `10`

#### Scenario: Нет поля order

- **WHEN** отобраны модуль без поля `order` и модуль с `order` `1`
- **THEN** система регистрирует модуль без `order` раньше

### Requirement: Провайдер модуля

Для каждого отобранного модуля система SHALL зарегистрировать класс `{namespace}{basename}\Providers\ModuleServiceProvider`, если он существует. `basename` система SHALL взять из записи кэша, найденной по `slug`. `namespace` SHALL быть настроенным пространством имён модулей. Если класса нет, система MUST NOT регистрировать провайдер этого модуля и SHALL перейти к остальным отобранным модулям.

#### Scenario: Класс провайдера есть

- **WHEN** класс провайдера отобранного модуля существует
- **THEN** система регистрирует этот класс

#### Scenario: Класса провайдера нет

- **WHEN** класс провайдера отобранного модуля не существует
- **THEN** система не регистрирует провайдер этого модуля и продолжает старт

### Requirement: Файлы autoload

Для каждого отобранного модуля система SHALL подключить каждый существующий файл из `autoload` и SHALL пропустить отсутствующий файл. Перед сборкой пути система SHALL применить настроенную карту путей к строке из `autoload`. Каталог модуля SHALL быть каталогом модулей плюс `basename` записи, найденной по `slug`.

#### Scenario: Файл существует

- **WHEN** `autoload` отобранного модуля называет файл, который есть в его каталоге
- **THEN** система подключает этот файл

#### Scenario: Файла нет

- **WHEN** `autoload` называет файл, которого нет
- **THEN** система пропускает этот файл и продолжает старт

#### Scenario: Поля autoload нет

- **WHEN** у отобранной записи нет поля `autoload`
- **THEN** система не подключает дополнительных файлов этого модуля

#### Scenario: Карта путей переписывает префикс

- **WHEN** карта путей заменяет фрагмент строки `autoload`, и файл по новому пути существует
- **THEN** система подключает файл по новому пути

### Requirement: Неотобранные модули

Система MUST NOT регистрировать провайдер и MUST NOT подключать файлы `autoload` у записи, которая не отобрана.

#### Scenario: Выключенный модуль с провайдером и файлами

- **WHEN** у записи `enabled` равен `false`, класс провайдера существует и файлы `autoload` лежат на диске
- **THEN** система не регистрирует этот провайдер и не подключает эти файлы

### Requirement: Поля вне загрузки

Система MUST NOT использовать `name`, `version`, `description` и `id` ни для отбора модуля, ни для выбора класса провайдера и путей `autoload`.

#### Scenario: Меняется только описание

- **WHEN** между двумя стартами у той же записи меняются только `name`, `version`, `description` или `id`
- **THEN** набор отобранных модулей и класс провайдера остаются теми же

### Requirement: Изменение кэша после старта

Система MUST NOT менять состав уже зарегистрированных модулей, если файл кэша изменился после старта. Следующий старт SHALL прочитать кэш заново.

#### Scenario: Модуль включили без нового старта

- **WHEN** модуль не был отобран при старте, и затем в кэше его `enabled` стал `true` без нового старта
- **THEN** модуль остаётся незарегистрированным до следующего старта

### Requirement: Отсутствующий кэш

Если файла кэша нет, система SHALL построить его по каталогам модулей и затем загрузить модули из построенного кэша.

#### Scenario: Манифест выключает модуль

- **WHEN** файла кэша нет, и манифест модуля задаёт `enabled` равным `false`
- **THEN** после построения кэша система не отбирает этот модуль

#### Scenario: В манифесте нет enabled

- **WHEN** файла кэша нет, манифест модуля не содержит `enabled`, и настроенное значение по умолчанию — `true`
- **THEN** после построения кэша система отбирает этот модуль
